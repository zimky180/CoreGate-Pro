## 适配方向

1. CPU：动态枚举 policy*、核心拓扑及真实可用频率档位，替换固定簇路径和专用频率。
2. GPU：分别处理 Adreno、Mali / Immortalis，读取可用节点及档位；不支持时跳过对应控制。
3. 温度：探测传感器类型、单位与可用性，明确温度来源。
4. 冻结：按系统能力识别支持情况，核实各厂商包名和恢复行为。
5. 能力状态：逐项报告锁核、CPU 限频、GPU 限频和温度支持情况，后续与 App 配套展示。

## 本地适配进度

已接入 hardware.sh，CPU 限频动态枚举全部 policy，优先按 scaling_available_frequencies、其次按 time_in_state 选取合法档位。最低最高频的簇使用 cap_little_mhz，其余簇使用 cap_big_mhz；三簇机型的中核与超大核共用大核目标，保持原版配置格式。无频率表时跳过限频。

GPU 支持 KGSL 及路径/名称可识别为 GPU 的 devfreq（含部分 Mali / Immortalis 驱动），按频率表区分 Hz / kHz；未知厂商私有节点不会控制。限频前备份原值与权限，恢复完成后清除快照；节点暂不可用或恢复失败则保留快照重试。不再以本机 1225MHz 作为恢复值。cap_gpu_pwrlevel=-1 表示不额外设置功耗档，显式非负档位仅用于能验证范围的 KGSL。

温度沿用上游实际的电池温度语义，依次探测电源 Battery 节点、明确为电池的 thermal_zone、dumpsys battery；不以 CPU/SoC 温度代替。temperature.state 的字段及 battery 标识保持兼容。

只读诊断入口：`sh /data/adb/modules/CoreGate/service.sh --hardware-status`，输出 core / cpu / gpu / temperature 四段，不初始化日志或配置。能力报告中的 detected / available 只代表节点可探测，不等同于实际控制通过。

首次安装默认全部关闭：enabled=false、auto_lock_count=0，限频、温度、冻结及其它布尔开关均为 false；不会自动选择或封锁最后一个大核。配置键名、App 命令与状态字段保持兼容。升级迁移保留已有用户配置，不在开机时重置设置。普通版与 Pro 沿用同一个模块 ID，不能同时安装运行。

核心控制直接向实际 cpuN/online 写入 0 或 1，然后回读；不绑定 CPU0、不限定八核或四核封锁上限，保留至少一个在线核。日常锁核按现有 poll_interval 检查实际状态，对被系统重新上线的选中核心每轮补锁一次；已经离线的核心不重复写入，不关闭厂商 core_ctl。旧版 core_ctl 备份仅用于恢复原值。手动选择优先于自动名单，包括手动全部开核后的空选择；恢复全部核心会清除手动选择。显式一次性操作可以重新发起请求。

当前仅完成模块侧通用适配与本地模拟验证，未刷入设备，也未进行多机型验证。现有 App 的频率档位列表、频率实况可能仍含固定 policy0/policy6、KGSL 假设，尚不能保证所有机型的界面显示与选档完整。厂商不允许 CPU 热插拔时，锁核同样可能不生效；冻结分组仍来自原版，未验证所有厂商组件。

验证覆盖三簇 CPU、真实档位向下取整、最小频率边界、缺失能力、恢复重试、Adreno Hz / Mali kHz、温度单位及只读查询。共享存储屏蔽 chmod 的实际权限变化，设备 sysfs 权限锁定/恢复仍需实测。本轮仅本地开发，不提交或上传 GitHub。

## v2.3.2-pro 锁核维持修复

修复相同封锁请求命中缓存后只查询、不再下锁的问题。日常场景每轮检查实际在线状态，对重新上线的选中核心补锁；每轮每核最多尝试一次，保留至少一核在线保护。游戏、录屏/相机、充电与高温解封仍由已有策略决定。补锁延迟取决于当前 poll_interval，不能保证系统不会在两轮之间重新开核。

已在模拟目录复现旧版失败并通过修复后回归检查；尚未在红米 K70 至尊版验证。

## v2.3.2-pro 二次复核

保留每轮补锁，并修复恢复方向的重试：解封时每次核对实际状态，仅对离线核心发起上线；更换封锁名单时，旧核心恢复失败保留旧请求供下轮重试；主开关关闭后的恢复失败也会重试。修正入口中残留的“仅应用一次”注释。

本地模拟覆盖重复补锁、解封失败重试、换名单恢复重试，以及真实 run() 调用链中的日常、游戏、主开关关闭分支。全部通过；未在红米 K70 至尊版刷入复测。间隔为配置的 sleep 时间加每轮检测执行耗时，初始化另有 20 秒观察等待；不能保证两轮之间持续离线。


## 游戏误回锁与限频恢复修复

- 游戏退出增加新一轮采集复核：连续两轮均未命中且各自复核也未命中才切回日常；真实息屏确认后仍执行息屏策略。退出游戏的锁核时间因此可能延后一个检测间隔。
- 游戏期间 sysfs 报息屏时用 dumpsys power 再核实；电源状态无法确认时保留游戏保护。
- 游戏/录屏匹配变量局部化，避免覆盖日志前台包名；退出复核记录屏幕状态及两次候选。
- 限频恢复失败向模式状态传播，显示 unlock_partial 并在后续循环继续重试；开机恢复、主开关关闭与一键恢复也检查失败。
- 普通版恢复写入增加回读，GPU恢复目标读取本机可用频率表，去掉固定1225MHz恢复假设。缺少频率表时报告未完成，不宣称恢复成功。
- 已通过两版共26项工作区模拟回归与脚本语法校验；尚未完成反馈设备真机复测，不能断言现场根因已被完全覆盖。
